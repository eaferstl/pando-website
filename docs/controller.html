Controller

The controller is a StatefulSet that receives evidence from sidecars over mTLS, writes it to a durable spool, and owns delivery to your SIEM, Slack and the portal. Without it, each sidecar handles its own delivery from an emptyDir that dies with the pod.

Optional, and separately installed

The controller is its own Helm chart, currently 0.1.0. The pando-webhook chart does not install it, and sidecars run and detect without it.

Install

helm install pando-controller \
  oci://us-central1-docker.pkg.dev/pandocore-prod/charts/pando-controller \
  --namespace pando-system --create-namespace \
  --set license.key="YOUR_LICENSE_KEY"

license.key is required unless you set license.existingSecret.name instead. portalURL is also required, and already carries the right default.

Pointing Sidecars at It

Installing the chart does not route anything to it. Two steps connect the two halves:

  1. Set PANDO_CONTROLLER_URL in the pando-webhook chart to the controller's evidence URL, which is https://<release>-pando-controller.pando-system.svc:9443 with the defaults above
  2. Mirror the pando-controller-client-tls Secret into every protected workload's namespace, so sidecars hold a client certificate

Ports

Port Transport Serves
9090 Plaintext /healthz and /metrics
9443 mTLS /evidence, /heartbeat, /siem/*

Security Posture

The controller runs unprivileged and holds no Kubernetes API access at all:

  • runAsNonRoot, UID 1000, readOnlyRootFilesystem, allowPrivilegeEscalation: false, all capabilities dropped
  • No hostPID, hostNetwork, hostIPC or hostPath mounts
  • Its ServiceAccount is deliberately bound to no Role and no ClusterRole. The controller reads a file and answers a socket; it never calls the API server

The Spool

Each replica gets a PersistentVolumeClaim, 2Gi by default. The default is 2 replicas, so that is two cluster-level volumes, not one per protected pod. It does not grow with the fleet.

The controller answers 202 only after an fsync, and replays whatever is on disk at startup. That is what makes it safe for the sidecar to drop a record once it has been accepted.

The spool is a delivery hop, not a history

A spooled record is unlinked once every configured destination confirms it. The controller guarantees that accepted evidence is not lost in transit; it does not retain evidence for you. For retention, deliver to a SIEM or the portal and apply your retention policy there.

Per-Namespace Destinations

When destinations.enabled is set, the controller mounts a Secret written by the admission webhook and re-reads it every 30 seconds. If the pando-webhook chart is not installed the mount is empty, the controller logs that once, and each namespace falls back to the portal and the environment baseline. The mount is optional by design, so the controller still starts.
